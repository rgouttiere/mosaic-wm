# Mosaic — guide contributeur (Claude)

Tiling/tabbing window manager pour macOS, en Swift (SwiftPM), **SIP activé → Accessibility (AX) uniquement**, pas d'API privée qui exige SIP-off.

## Build / test / run
- **Valider la logique** : `make test` → build debug + `.build/debug/Mosaic --self-test` (suite de tests purs : arbre de layout + parsing config). **Doit rester VERT à chaque changement.**
- **Produire l'app** : `make bundle` → build release + `Mosaic.app` signé avec l'identité stable « Mosaic Self-Signed » (bundle id `fr.rgouttiere.mosaic` → conserve le grant Accessibilité entre rebuilds). `make run` = bundle + lance. **La recette vérifie la signature obtenue et échoue si elle est ad hoc** : `codesign` peut échouer en silence contre un trousseau verrouillé et laisser la signature ad hoc du linker — pour TCC c'est une app inconnue, le grant ne s'applique pas, l'énumération AX rend **vide** et Mosaic tourne en gérant zéro fenêtre, sans alerte (01/10/2026, 10 min de bureau sans tiling). Rituel de déploiement : **`make deploy`** (= `make test` **puis** bundle avec vérification de signature **puis** `make restart`, qui fait `launchctl kickstart -k` sous l'agent). Les tests sont dans la cible, pas dans une chaîne shell : `make test 2>&1 | grep … && make deploy` rapporte le statut du `grep`, et a laissé partir un binaire qui plantait au lancement (`try!` sur un regex invalide) — sous `KeepAlive` c'est une boucle de respawn (03/10/2026). Un `try!` au chargement d'un type est un crash au lancement : les regex se construisent en `try?` avec repli. Mosaic tourne sous un **LaunchAgent** (`make agent`, `~/Library/LaunchAgents/fr.rgouttiere.mosaic.plist`, `KeepAlive SuccessfulExit=false`, `RunAtLoad`) : un crash est relancé en quelques secondes, Quit depuis le menu (exit 0) reste quitté. Une instance lancée **à la main** (Quit depuis le menu puis Spotlight/Finder — arrivé le 03/10 : vingt minutes de déploiements à vide, l'instance de l'agent trouvant l'instance manuelle et sortant) **se rend à launchd** au démarrage : `main.swift` compare `XPC_SERVICE_NAME` (= le label du job sous launchd, `application.<bundle>.<n>` via LaunchServices) et le programme du plist, fait `launchctl kickstart` et sort ; la garde d'instance unique attend 2 s qu'une autre instance disparaisse avant de céder. `make restart` tue d'abord **toute** instance, pas seulement celle du job. `doctor` signale une instance hors agent. Et une instance qui ne gère rien se tue avec `kill -9` (un quit normal passe par `saveNow`), après `cp state.json state.json.good`.
- Itérer vite : `swift build` compile ; `swift run Mosaic --self-test` marche aussi.
- Config live de l'utilisateur : `~/.config/mosaic/config.json` (hot-reload via file-watch) ; état : `~/.config/mosaic/state.json` ; diag : `mosaic dump-layout` (imprime le dump, aussi dans `/tmp/mosaic-dump.txt`) et **`mosaic doctor`** (bilan de santé : signature, AX accordé *et effectif*, enregistrement d'écran, API privées, invariants, âge de `state.json`, dernier crash) ; journal des décisions : `~/.config/mosaic/mosaic.log`. **CLI = socket Unix** `~/.config/mosaic/mosaic.sock` (`CommandServer`, 0600) : une ligne, une réponse « statut puis corps » ; `query` est **vivant** (même dictionnaire que `status.json`, repli sur le fichier si l'app est absente), action inconnue = erreur. L'écoute est sur la main queue, chaque client servi en arrière-plan avec timeouts, seul le handler saute sur main — un client bloqué ne gèle jamais le WM. **Auto-diagnostic** toutes les 30 s (`healthCheck`) : zéro fenêtre gérée alors que ≥ 2 fenêtres d'apps sont à l'écran = un grant Accessibilité qui ne s'applique pas → `▦!` dans la barre, une alerte, `healthy: false` dans `status.json`. Une panne silencieuse est une panne qu'on découvre dix minutes trop tard ; tout ce qui peut échouer sans bruit doit avoir sa ligne dans `doctor`.
- **Parseur de config = une table** (`Config.options`) : une option = sa propriété + une entrée (lecture, reset, sérialisation dérivés). Toute modification du parseur se **prouve** par équivalence : `MOSAIC_CONFIG=<fichier> .build/debug/Mosaic --dump-config` avant/après, sur la vraie config + une config qui pousse chaque clé hors défaut + des configs de torture (types faux, clés inconnues, hors plage) + le fichier écrit sur config absente — le diff doit être vide. C'est ce filet qui a révélé que « le dernier gagne » sur une collision `workspaceNames` tirait au sort selon l'ordre du `Dictionary` (corrigé : clés triées).

## Branches

  supprime et ce qu'elle coûte : `docs/V2-EMULATED-WORKSPACES.md`.
- **`v0.5.2-alpha`** = dernier état en **Spaces macOS réels**, point de repli si v2 s'avère
  intenable (`git checkout v0.5.2-alpha`).
- `v2-emulated` = fusionnée dans `main` ; le travail continue sur `main`.

## Architecture (v2 émulé)
Un **seul** Space macOS. Un « workspace » = ensemble logique de fenêtres. Switch = **park** (déplacer hors écran) / **unpark** (à l'écran) via `Container.arrange(in:)`. `shownOnDisplay: [displayID: workspace]` est **possédé par nous** (jamais lu du window-server). **Model A** : workspaces 1-9 globales, chacune épinglée à un moniteur (`assignedDisplay` / `WindowManager.monitorBlock`, pures + testées). Cœur = arbre `Container` (splits / tabbed / stacked), intact depuis v1.

## Invariants load-bearing (coûteux à re-découvrir)
- **Z-order par couche d'APP** : macOS empile par app d'abord ; `AX.raise` (kAXRaiseAction) ne réordonne que *dans* une app. Pour passer une app au-dessus d'une autre → **`NSRunningApplication.activate()`** (cf. `liftAppsAboveParked`, appelé au switch sur les workspaces multi-apps).
- **Ne JAMAIS `AX.raise` une fenêtre fullscreen native** : ça tire son Space au premier plan de façon incontrôlée.
- **Park géométrie** (`Geometry.parkRect`, pure + testée) : pousser hors du bord **du moniteur d'attache** qui donne sur le vide (le plus à droite→droite, à gauche→gauche, **intérieur→bas**). Jamais en **coin** (macOS shrink la hauteur → fenêtres qui reviennent raccourcies). Jamais cross-résolution (sinon clamp → resize).
- **Park = cacher quand on peut, déplacer sinon** (`WindowManager+Park`, `hideConfinedApps`). Le window server garde ~40 px d'une fenêtre déplacée et l'alpha est mort : le park par déplacement laisse un sliver que les tuiles recouvrent. `NSRunningApplication.hide()` n'a rien de tout ça — instantané, rien à l'écran, un appel par app — mais cache **toutes** les fenêtres de l'app. Donc seulement pour une app **confinée** à la workspace parquée (règle pure `confinedPids`, testée) : toutes ses fenêtres gérées y sont, aucune fenêtre non gérée à l'écran, pas de plein écran natif, pas le scratchpad. Pendant qu'une app est cachée par nous (`ManagedWindow.parkHiddenPids`), `windowRect(forTile:)` n'écrit rien pour ses fenêtres : elles restent sur leurs tuiles, invisibles, et l'unpark = `unhide` + des écritures que le cache saute. Ce qui tenait déjà : `reconcile` garde les slots d'une app cachée (le cas ⌘H), `AX.managedWindows` saute les apps cachées (pas de ré-insertion), `syncFocusToSystem` bascule sur la workspace d'une fenêtre parquée remise devant (Dock, ⌘Tab). Quit et `unparkAll` dé-cachent tout. L'exposé ne recapture pas la miniature d'une fenêtre cachée (il garde la dernière). **Désactivé par défaut depuis le 03/10** : mesuré sur six allers-retours ws1⇄ws2, la bascule passe de 180 à 382 ms en moyenne et de 0,65 à 1,4 s au pire — les apps se redessinent à l'unhide et chaque appel AX vers une app qui se réveille bloque le thread principal. Trois défauts structurels corrigés au passage, valables même option coupée : cacher l'app au premier plan fait activer la suivante par macOS (`activateBeforeHiding` met la fenêtre entrante devant avant le hide) ; `syncFocusToSystem` ne plante plus une feuille d'un autre écran comme focus de la workspace active (c'était « le focus reste sur Alacritty ») ; les pids cachés sont écrits dans `~/.config/mosaic/.hidden-pids` et dé-cachés au démarrage suivant avant la restauration (un kill -9 laissait WhatsApp invisible et sa workspace « kept for a later visit »), et SIGTERM passe par un quit normal. `make restart` ne fait plus de `killall` avant `kickstart -k` : launchd relançait l'instance tuée, kickstart la retuait, et la remplaçante attendait le throttle de 10 s — deux restaurations par déploiement, la première tuée en vol.
- **`screen(forWorkspace:)` = 3 conditions** : `spaces[n]` existe + `ws.displayID != 0` + `shownOnDisplay[did] == n`. Au **dock**, `ensureAllPresentMonitorsShown` doit re-homer **tous** les moniteurs présents (pas que celui sous la souris), sinon écrans vides.
- **Reconcile** : fast-path si `onScreen` inchangé ; passes de confirmation (+0.3/+0.8s) pour les fenêtres qui matérialisent tard ; **jamais** de `CGWindowList` en boucle sur le timer (tue l'App Nap) — garde-fou à vérifier sur **multi-écrans**, celui de `purgeVisibleGhosts` ne se fermait jamais à 3 moniteurs et tournait donc à plein régime en permanence.
- **Restore au lancement** : restaurer **TOUTES** les workspaces d'un coup depuis un pool partagé (sinon la 1re visitée avale les fenêtres des autres). Appariement par étages (`takeMatch`) : id+bundle → bundle+titre → **bundle+frame** (`SavedWindow.frame`, le rect AX au moment du save : Mosaic l'a posé là, et après un reboot les apps qui restaurent leur géométrie — navigateurs — y reviennent ; `Geometry.frameMatchIndex`, pur + testé, tolérance 6 px de taille / 60 px d'origine) → bundle seul si non ambigu. L'étage frame comble le trou des fenêtres d'une même app dont le titre a changé (onglet, cwd) : avant, deux Chrome au titre modifié revenaient en insertions fraîches.
- **`setCocoaFrame`** cache `lastSetFrame` **uniquement si l'écriture AX a réussi** (sinon la prochaine render ré-émet).
- **Tuiles disjointes** : deux tuiles ne se chevauchent jamais, donc leur ordre de profondeur est invisible. Le seul empilement qui compte est **dans un groupe d'onglets**. Une passe qui remonte « toutes les fenêtres visibles » à chaque render est du cross-process pour rien (`raiseOutOfOrderTabs` ne remonte que les groupes réellement mal empilés, en lisant l'instantané ordonné avant→arrière).
- **Jamais deux écritures de frame sur la même fenêtre dans un render** : `arrange` plaçait chaque onglet caché sur sa tuile et `parkHiddenCrossAppTabs` le repoussait juste après — chacune défaisait l'autre, donc le cache `lastSetFrame` ne sautait **jamais**. Le park est seul écrivain (`Container.parkedOffScreen`), libéré pour l'onglet qui devient sélectionné et pour un groupe qui cesse de qualifier. **Il y a DEUX chemins de placement des onglets cachés, pas un** : `layoutTabbed` et `layoutStackEntry` (groupes empilés, rangées-feuilles et entrées imbriquées). La règle n'avait été posée que sur le premier ; le second replaçait chaque rangée cachée sur sa tuile à chaque render et le park la repoussait — « 2 écritures dans un render, à répétition » sur les six entrées d'une workspace empilée (03/10/2026, trouvé par l'invariant à la minute où la structure a été construite). Toute règle sur les onglets cachés se pose sur les deux, via `windowRect(forTile:)` qui est le seul endroit du calcul de slot.
- **L'amorçage coûte UNE double écriture par fenêtre — mesuré, pas supposé.** À son premier placement, une fenêtre est écrite deux fois : `arrange` pose l'onglet caché cross-app sur sa tuile puis le park le repousse et arme `parkedOffScreen` (arrange s'abstient ensuite) ; une fenêtre aspect-locked est placée puis re-fit une fois son ratio appris. En régime établi ça ne se répète pas — le compteur (`ManagedWindow.maxFrameWrites` / `doubleWriteRenders`, epoch bumpée par render/renderLive) reste muet après un `recover`, sur 30 s et des switches qui re-rendent IINA. Mais le **boot** place tout en plusieurs rounds (restore eager, puis le settle des écrans qui ré-asserte), et une fenêtre aspect-fit y est re-fittée à chaque round : « 2 renders » sept secondes après un lancement propre, mesuré. D'où le reset de l'audit à la fin du boot (le timer des 20 s qui ferme aussi les `restoreHints`), comme `recover` le fait après son propre heal. Et **chaque `reassertAllWorkspaces` ouvre sa propre epoch** : un cycle undock → redock → réveil enchaîne une vingtaine de passes (settles d'écrans + 3 étapes de réveil, caches invalidés à chaque fois) sans aucun `render()` entre elles puisque personne n'est au clavier — comptées dans une seule epoch elles donnaient « 24 écritures dans un render » sur toutes les fenêtres (mesuré le 01/10/2026) alors que rien ne se battait. Les passes se lisent dans le journal (`reassert all workspaces — wake step k/3`, `display set settled`). D'où le seuil de l'invariant `double-frame-write` : seule la **récurrence** est un conflit ; alerter dès la première ferait sonner l'alarme sur chaque fenêtre. Les écritures de sonde (le monocle qui gonfle une fenêtre pour lire sa taille contrainte) passent `probe: true` et ne comptent pas.
- **Un nettoyage partiel laisse un état SANS SORTIE.** Trois bugs le même jour, même motif : `dedupTrees` ne dédupliquait qu'**entre** Spaces (trois feuilles d'une même Space survivaient → `arrange` écrit la fenêtre trois fois, la dernière gagne, elle atterrit hors de son moniteur) ; le relâchement de `parkedOffScreen` ne visitait que les groupes d'onglets **encore existants** (une feuille qui quitte son groupe le garde à vie, et `arrange` refuse de replacer une feuille parquée → fenêtre abandonnée à 40 px de l'écran) ; `ensureAllPresentMonitorsShown` ne re-homait que la workspace **affichée** (une parquée au `displayID` périmé — les ids changent à une reconfiguration — tombe à 0, et `screen(forWorkspace:)` exclut 0 par construction → ses fenêtres sont enfermées à jamais). La forme du remède est toujours la même : **relâcher / valider sur TOUT l'ensemble, puis ré-armer le sous-ensemble légitime**, jamais filtrer en entrée.
- **Ordre des deux écritures AX** (`Geometry.positionFirst`) : les attributs position et taille s'écrivent séparément, donc la fenêtre existe brièvement en géométrie mixte — et macOS clampe ce qui dépasse un bord. Une fenêtre qui **rétrécit** se redimensionne donc d'abord, puis se déplace (sinon on déplace une fenêtre encore grande, son origine est clampée, et la taille écrite ensuite atterrit sur une origine faussée) ; une fenêtre qui **grandit** fait l'inverse.
- **La pile a deux rendus, un seul modèle** : `stackStyle` `rows` (rangées pleine largeur en haut, une hauteur de barre chacune) ou `rail` (colonne d'icônes à gauche, `railWidth`). C'est un **mode** de `TabBarView` (`rail`), pas une seconde vue : mêmes `rows`/segments/sélection, mêmes clics, drags, molette et survol — seules la géométrie (`rowHeight`, `rowIndex(at:)`) et le dessin (`drawRail`) changent. Les non-lus viennent de `UnreadBadge.parse` sur le titre déjà lu pour la rangée (zéro appel AX de plus) : seul un groupe parenthésé de chiffres compte, « (Channel) » ou « (3 participants) » non. Né du constat qu'une pile de quatre rangées à 30 px mangeait 13 % de l'écran du laptop. Les icônes viennent de `NSRunningApplication.icon`, qui renvoie la **variante du style d'icônes système** (Réglages → Apparence → « Style des icônes et widgets », clé `AppleIconAppearanceTheme`) : le rail suit le réglage Sombre/Teinté de macOS 26+ sans rien faire — vérifié le 03/10/2026 avec `RegularDark`.
- **Une seule implémentation de la géométrie** : `Container.runLayout(in:visibleOnly:apply:into:)` — `apply` vrai déplace les fenêtres et place les strips, faux se contente d'enregistrer les rects (`previewFrames`, dont l'exposé a besoin parce qu'une fenêtre parquée est clampée dans un coin et a perdu sa disposition). La deuxième copie qui existait pour le preview **avait dérivé** : un stack contenant un split n'y était pas subdivisé, donc l'exposé affichait faux. Ne jamais réécrire un second calcul de tuiles ; et un preview ne doit **rien muter** (`normalizeRatios` et le clamp de `selected` restent sous `apply`).
- **Jamais un appel AX sans timeout** : `AX.installMessagingTimeout()` au tout début du lancement (élément *system-wide* → sert de défaut à tous les autres). Chaque appel AX est un aller-retour **synchrone** dans l'app cible ; quand celle-ci ne répond plus (beachball, swap, lancement en cours), l'appel n'échoue pas vite, il attend le défaut système — des secondes — et le thread principal attend avec lui. Un render fait des dizaines d'appels sur chaque app tuilée, donc **une seule app bloquée fige tout Mosaic**. Le cache 50 ms n'aide pas ici : il amortit la lenteur ordinaire, pas une app qui ne répond rien. Un appel coupé se lit comme une écriture AX échouée, donc `setCocoaFrame` n'avance pas son cache et le render suivant ré-émet — le chemin de reprise existait déjà. Ne pas retirer en croyant à une précaution gratuite ; remonter la valeur si une app lourde met deux renders à se placer.
- **Les caches par fenêtre (frame, plein écran, titre) sont invalidés par les notifications AX, pas par un TTL court** : plusieurs passes d'un render relisent la même fenêtre (letterbox, bordures, halo, aspect-fit, park des onglets cachés, reconcile) et chaque lecture est un aller-retour dans l'app — le coût d'un render est alors fixé par l'app la plus lente de la disposition, pas par ce qu'il y a à dessiner (IINA : `decorate` 6 → 116 ms). Jusqu'au 04/10 le cache de frame et de plein écran durait 50 ms : mesuré, **616 lectures AXFullScreen pour dix changements d'onglet**, 537 en 45 s de repos, et l'une d'elles décroche à 500–700 ms dès qu'une app est occupée (Chrome, WhatsApp, KeePassXC). Désormais chaque fenêtre gérée est observée pour `kAXWindowMoved`/`Resized` (en plus de Destroyed/TitleChanged) ; la callback appelle `noteExternalChange` qui jette le cache concerné — **et rien d'autre** : nos propres écritures reviennent en écho par ces notifications, un re-tile dessus bouclerait. Les TTL restent en filet (frame 1 s, plein écran 2 s, titre 5 s) pour une app muette. Piège trouvé en branchant ça : `startObserving` restaure les fenêtres **avant** `observer.start()`, et `watchForClose` sautait en silence toute fenêtre dont l'app n'avait pas encore d'observer — les fenêtres restaurées n'ont jamais reçu de notification (titre, fermeture, déplacement) jusqu'au 04/10 ; `watchForClose` crée désormais l'observer de l'app à la demande. Toute écriture invalide ; la relecture dans `setCocoaFrame` **alimente** le cache au lieu de le contourner. Même logique de perception côté strip : `flushStripSelection` peint la nouvelle sélection d'onglet ou de rangée **avant** le render (`displayIfNeeded` + `CATransaction.flush`), parce que le render qui suit coûte 50 à 600 ms d'AX et que l'œil attendait tout ce temps sans réponse.
- **Les règles s'appliquent à l'insertion ; `followTitle` les ré-applique au changement de titre** (`WindowManager+Reroute`, 04/10). Une fenêtre kitty naît « zsh » et ne dit « k8s · k9s » qu'une fois tmux attaché, bien après le test de règle de l'insertion. Garde-fou : `ManagedWindow.lastTitleRoute` mémorise la règle appliquée, et on ne re-route que si la règle **change** (sinon chaque tick de titre tmux, « k8s · zsh » → « k8s · k9s », annulerait un déplacement manuel). Piège de test : `kitten @ launch --os-window-title` **fige** le titre de la fenêtre macOS — ni tmux ni AXTitleChanged ne le changent plus, ce qui a fait croire que kitty n'émettait pas de notification de titre ; sans ce flag les notifications arrivent. Déplacer une feuille d'une workspace quelconque passe par `detach(_:from:)` / `replace(_:with:in:)` : les variantes sans `ws` éditent `root`, donc la workspace **active**, et vidaient la racine active quand la feuille était la racine de la sienne.
- **Atténuer = assombrir, jamais rendre translucide.** Le dim des écrans sans focus (`dimInactiveMonitors`, `inactiveMonitorDim`) baissait l'`alphaValue` des strips : la fenêtre derrière transparaissait dans le rail frosted, et l'utilisateur ne veut **pas de transparence**. Depuis le 04/10 : un voile noir opaque au-dessus du strip (`TabBarWindow.setDim`, `VeilView` dont `hitTest` rend nil pour laisser clics, drags et tooltips au strip) et un accent **mélangé vers le noir** pour les bordures inactives — même facteur, aucun alpha. Coût nul : un calque statique, une écriture de propriété au changement d'écran actif.
- **Rien de synchrone vers une app ou le window server qui ne soit indispensable à ce que l'œil attend** (chantier du 04/10, mesuré avec `.timing` : onglet cross-app 204 → 23 ms, rail 112 → 30 ms, bascule de workspace 180 → 47 ms, reconcile 30 → 0,1 ms, repos quasi muet). Les règles qui en sortent : **(1)** une écriture de park passe par `setCocoaFrameAsync` — une file série **par fenêtre**, le cache prend le rect demandé, une écriture synchrone ultérieure sur la même fenêtre vide d'abord sa file (`drainParkWrites`) ; `ManagedWindow.parkingWrites` route tout `setCocoaFrame` d'un `parkWorkspace` vers cette file ; **(2)** `AX.setFrame(onlyChanged:)` n'écrit que la composante qui change, et un déplacement à taille constante ne relit pas (`ax.frameReadback` : rien à apprendre d'un clamp impossible) ; **(3)** l'écho Moved/Resized de notre propre écriture est ignoré pendant 0,5 s (`lastWriteAt`), sinon il jetait le cache et la lecture suivante tombait dans l'app en plein relayout ; **(4)** le halo vit un niveau au-dessus des autres overlays et n'est plus ré-ordonné à chaque show (`halo.show` 31 → 1,5 ms), le fantôme du fondu reste monté à alpha 0 ; **(5)** notre propre activation (`isOwnActivation`, 1 s après `focusAssertedAt`) ne déclenche pas de reconcile ; **(6)** `onScreenSnapshot` périmé sert la dernière liste et la rafraîchit en arrière-plan (`snapshot.async`), un reconcile suit si la liste a changé — `CGWindowListCopyWindowInfo` coûtait 40 ms de moyenne et 500 au pire juste après une bascule, le window server étant occupé par les relayouts ; **(7)** la chauffe des miniatures capture en série, à 800 px, et seulement les fenêtres dont l'aperçu a plus de 15 s ; **(8)** le chemin lent du reconcile n'interroge en AX que les apps qui possèdent une fenêtre à l'écran **inconnue** de nos arbres (`reconcile.captureApps`) — `captureWindows` demandait ses fenêtres à chaque app à l'écran, 260 ms de moyenne après une bascule de workspace, pour n'en garder aucune. Un premier `decorate` après le lancement peut coûter ~1 s (création des fenêtres overlay pendant que le window server digère la restauration) : une fois, pas un régime. Ce qui reste et qu'on ne rattrapera pas : l'écriture de la fenêtre entrante (12–18 ms, l'app relayoute) et son `activate` (6 ms).
- **Une frame de resize live = deux écritures AX et rien d'autre qui parle aux apps.** Mesuré (rafale clavier sur Chrome + Firefox, `.timing`) : `renderLive` 67,6 ms par pas au départ, dont seulement 1 ms de décorations — le goulot n'était pas ce qu'on dessine mais ce qu'on **demande aux apps** pendant qu'elles relayoutent : la relecture de frame après chaque écriture (11 ms, autant que l'écriture), les titres d'onglets relus par `layoutTabbed` (un aller-retour par onglet par frame), `isFullscreen` relu par chaque passe d'overlay (7–9 ms à eux seuls), l'id de fenêtre et un `CGWindowList` frais pour le halo. Une app occupée à relayouter ne répond pas avant d'avoir fini, donc chaque lecture coûte le temps de *son* relayout. Règles : pendant `ManagedWindow.liveResize`, `setCocoaFrame` ne relit pas (cache optimiste = la géométrie demandée, que bordures/voile/letterbox suivent de toute façon ; `learnResizeMins` relit la vérité au settle), les titres ne sont pas rafraîchis (`visibleOnly`), `isFullscreen` cache sa valeur sans limite d'âge (l'état ne change pas en plein drag ; hors drag, TTL 50 ms pour que « jamais raise une fenêtre fullscreen » reste vrai), le halo ne fait que **bouger** (`moveFocusIndicatorLive`) et il est en **couches CA** (`CAShapeLayer` + `shadowPath`, composé par le GPU : 1,8 ms par frame contre 4–10 en `draw(_:)` avec `NSShadow`), et les trois pools d'overlays (bordures, letterbox, voiles) ne touchent pas une fenêtre dont le frame n'a pas changé (`invalidateAll()` au reload de config pour les couleurs). Résultat 34–44 ms par pas, dont 25–28 ms = les deux `AX.setFrame`. Le plancher suivant est structurel : sortir l'AX du thread principal.
- **AX hors thread principal : NON, pas sur ces chiffres.** Une nuit de `.timing` (154 min actives, 23 500 ticks) : le thread principal est occupé **~1–2 %** au repos (timer 4,4 ms/tick dont `sweepStrips` 2,9 ms, `reconcile` 74 ms × 453, `render` 143 ms × 63 — ces moyennes sont gonflées par les réveils). Le mal n'est pas le débit mais les **décrochages** : maxima de 0,7 à **3 s** sur des appels synchrones (window server occupé au réveil : `orderOut` d'un strip 2,9 s ; app qui ne répond pas : `captureWindows` 1,6 s = le timeout AX de 1,5 s, `setFrame` 0,7 s). Un refactor async changerait la *forme* du décrochage, pas sa cause, pour un coût de cohérence élevé. À la place, les trois sources mesurées ont été coupées : `sweepOrphanStrips` et `DropHighlight.hide()` ne touchent plus une fenêtre déjà cachée (c'étaient des allers-retours window-server à vide, 2,5×/s) ; `reconcile` ne demande plus son id à l'app pour une feuille que `CGWindowList` liste déjà à l'écran (26 ms par reconcile). Reste connu : `captureWindows` ~100 ms sur le chemin complet (un `subrole` par fenêtre énumérée) — rare, seulement quand le jeu de fenêtres change. Revoir la question async seulement si un `.timing` montre un thread principal **occupé**, pas un thread principal **bloqué**.
- **Une seule énumération `CGWindowList` par render** : `onScreenSnapshot` (TTL court), invalidé par le reconcile dès que le jeu de fenêtres change. Deux appels coûtaient ~3 ms chacun.
- **Minimum de resize plafonné** à `Geometry.maxLearnedMinShare` (0,45) de la paire : à 1/2 les deux minimums se rejoignent, `lo == hi`, et le séparateur gèle jusqu'au redémarrage. Ne jamais apprendre un minimum d'une fenêtre **fullscreen** ou sous **monocle** — elles rapportent l'écran entier.
- **Jeu en plein écran fenêtré** : subrole `AXUnknown`, `AXFullScreen=false`, et le clamp AX laisse ~40 px à l'écran donc `cgOnScreen` reste `true`. Le yield se décide sur **l'app au premier plan**, jamais sur le z-order : Mosaic remonte ses propres tuiles à chaque render, donc un test de z-order se désactiverait lui-même définitivement.
- **`status.json`** : ne pas republier un contenu identique. Chaque écriture réveille ce qui le surveille, et une barre externe qui redessine ses pastilles ne distingue pas une ré-émission d'un vrai changement.
- **Notch (laptop seul)** : `layoutRect` réserve `Config.notchBarOffset` (défaut 40) quand `screens.count==1 && safeAreaInsets.top>0` — **doit matcher** le `y_offset` de la sketchybar (config externe de l'utilisateur, hors repo).

## Veille / réveil (le plus cher à re-découvrir)
- `handleWake` est branché sur **deux** notifications (`didWake` + `screensDidWake`) : une seule veille déclenche la séquence deux fois. Étapes en `DispatchWorkItem` annulables, annulées à l'entrée (la 2e notification se fond dans la 1re) et à chaque veille.
- **`suspended` = ensemble de raisons** (`SuspendReason` : `sleep`, `displayChange`, `locked`), chacun ne relâche que la sienne. `locked` suit `com.apple.screenIsLocked/Unlocked` (DistributedNotificationCenter) : sous l'écran de verrouillage `loginwindow` est l'app frontale et rien de vrai n'est lisible ; à la sortie, un resync différé (`checkSpaceChange` + reconcile + focus). Une veille qui chevauche un verrouillage ne libère pas la raison de l'autre. En booléen partagé, un changement d'écran qui se stabilisait pendant une veille levait la suspension **de la veille**, et le reconcile repartait sur des fenêtres endormies.
- **Toute étape différée passe par `WindowManager.later(_:in:whileSuspended:acrossSleep:)`**, qui capture `sleepGeneration` (incrémentée à chaque veille) et respecte `suspended` **par construction** — un `asyncAfter` nu avait fini par oublier sa garde (le render post-drop). Les dérogations sont explicites au site d'appel : `whileSuspended` pour les étapes qui *lèvent* la suspension (réveil, settle d'écrans), `acrossSleep` pour ce qui doit survivre à une veille (le settle d'écrans, sinon `.displayChange` reste armé à jamais ; la sauvegarde ; la fin de boot). Un nom = debounce (remplace le précédent) + annulation par nom.
- **Ne rien re-dériver tant que les écrans ne sont pas tous revenus** : `assignedDisplay` mappe par **index** gauche→droite, donc avec un seul écran présent tous les workspaces s'y résolvent. Publier ces états transitoires redistribue le bureau plusieurs fois par seconde (et fait recharger la barre externe). `handleDisplayChange` force après 1,5 s de stabilité — c'est ce qui distingue un ensemble réduit *réel* d'un ensemble en train de se remplir.
- **L'absence d'une fenêtre de l'énumération AX n'est pas une preuve de fermeture.** Pendant `wakeGraceUntil` (30 s), 25 ratés au lieu de 2 — dans `reconcile` **et** dans `purgeVisibleGhosts`, qui possède les moniteurs visibles non actifs et était le chemin par lequel une veille longue redistribuait une disposition entière.
- **Trackpad au réveil : retenir les devices, n'arrêter que ce qui tourne, ne jamais relâcher.** `MTDeviceCreateList` rend des devices que seule la liste possède ; une fois la liste relâchée il ne reste qu'**une** référence et elle n'est pas à nous (retain count 1 après start, mesuré). Quand un device a disparu pendant la veille, le thread du framework relâche cette dernière référence en sortant ; si notre `cmt_stop` → `MTDeviceStop` vient de passer, le dealloc (`__MTDeviceRelease`) rappelle `MTDeviceStop` sur un device déjà arrêté : `CFMachPortGetPort(NULL)`, SIGSEGV sur le thread de MultitouchSupport, 20 ms après l'événement de réveil, Mosaic disparu sans alerte (01/10/2026 02:22, 11e réveil de la nuit — la course demande qu'un device ait disparu pendant la veille). Remède dans le shim C : `CFRetain` de chaque device, `MTDeviceIsAlive`/`MTDeviceIsRunning` avant tout stop, références jamais relâchées (un MTDevice fuité par réveil), et le restart différé de 2 s après `didWakeNotification` pour ne pas chevaucher le démontage du framework. **Et un seul redémarrage par réveil (04/10)** : la nuit, le Mac se réveille toutes les 30 min sans allumer les écrans (Power Nap) ; macOS livre à l'app le `didWake` de chacun de ces réveils **au réveil réel suivant** — 17 d'un coup à 10:12, 17 stop/start de MultitouchSupport en 130 ms, et Mosaic est mort deux fois de suite **sans rapport de crash** (ReportCrash n'en écrit plus pour un process qui a bouclé la veille). `scheduleWakeRestart` fond la rafale en un redémarrage 2 s après la *dernière* notification, jamais deux en moins de 10 s, et l'enregistrement initial attend 3 s après le lancement. `make restart` envoie désormais SIGTERM avant de relancer (sortie propre, code 0, puis `kickstart` simple) : la ligne « did not exit cleanly » ne doit apparaître qu'après une vraie mort. Comme le rapport peut manquer, `applicationWillTerminate` pose `~/.config/mosaic/.clean-exit` : au démarrage suivant, son absence est journalisée (« did not exit cleanly … »), rapport ou pas. Et comme ReportCrash a cessé d'écrire pour nous (quatre morts le 04/10, zéro rapport), **`CrashHandler`** écrit notre propre rapport sur SIGSEGV/SIGBUS/SIGILL/SIGABRT/SIGTRAP/SIGFPE : la backtrace du thread fautif dans `~/.config/mosaic/crash-latest.txt` (primitives async-signal-safe seulement, puis re-raise), que le démarrage suivant journalise avec ses huit premières trames. Troisième garde-fou : un redémarrage trackpad dont le timer part avec plus de 5 s de retard (process gelé au réveil, 17 s mesurés) est repoussé de 5 s au lieu de tomber dans la bousculade.
- Une feuille détachée note son workspace (`rememberReturn`) : la fenêtre qui revient y retourne au lieu d'atterrir dans le workspace actif. Consulté **après** les hints de relance, pour qu'un vrai redémarrage d'app garde la priorité.
- **`state.json.prev`** : point de restauration décalé (30 min). Les sauvegardes tournent en continu, donc quand on constate qu'une disposition est cassée la bonne version est écrasée depuis longtemps. `cp state.json.prev state.json` Mosaic arrêté, puis relancer. La copie ne se laisse pas écraser par une disposition **plus petite** (perdre des fenêtres est l'événement qu'elle doit survivre) — **sauf au-delà de 24 h** : la garde avait gelé la copie deux jours parce que l'utilisateur avait fermé deux fenêtres (12 → 10), et une sauvegarde censée avoir quelques minutes de retard qui en a un jour ne protège plus rien (`doctor` : « backup 57 h ago », 01/10/2026).

## Conventions
- **Self-tests verts** obligatoires ; garder `parkRect`/`monitorBlock`/`resizeLimits`/`covers`/`aspectFit`/`positionFirst`/`escapesTile` **pures + unit-testées** (ajouter un test avec toute nouvelle logique géométrique). `previewFrames` n'est plus une fonction à part : c'est `runLayout` en mode mesure.
- **Invariants** : `mosaic dump-layout` finit par `--- invariants (OK) ---`, ou par la liste des violations nommées (`duplicate-leaf`, `workspace-without-display`, `parked-but-visible`, `window-off-tile`, `dead-leaf`). Le jugement est **pur** — `LayoutSnapshot.violations()` travaille sur des structs plates, sans `Container` ni `ManagedWindow` — donc un état impossible se fabrique en trois lignes dans un self-test au lieu d'exiger de vraies fenêtres. Tout nouvel état impossible découvert s'ajoute là, **avec ses cas négatifs** : sans les exemptions (un onglet caché est légitimement parqué, une fenêtre letterboxée est plus petite que sa tuile, le plein écran et la source du PiP sont hors-jeu, une workspace vide sans display est bénigne, deux ids AX non résolus ne sont pas des doublons), les gardes crieraient en permanence et on finirait par les ignorer.
- **Journal des décisions** (`Log.event`) : toute décision **structurelle** passe par lui, jamais par `NSLog` seul — insertion d'une fenêtre *et la branche qui l'a décidée* (règle, hint de relance, hint de retour, preselect, groupWith, colonne, master-stack, après le focus), dédup, drop, move, switch, restore (comptes `matched/wanted`), re-home d'écrans, scratchpad, float, recover, veille/réveil, verrouillage. `NSLog` est invisible pour le bundle signé (mesuré : 710 lignes de log unifié en trois minutes, aucune de nous) ; `Log.event` écrit sur disque **et** dans un anneau mémoire de 200 lignes dont `dump-layout` imprime les 40 dernières (`--- recent events ---`). Un dump est la photo du résultat ; sans les décisions qui précèdent, chaque incident se reconstruisait à l'envers depuis la disposition survivante. Coût maîtrisé parce que ce sont des **événements**, jamais du per-render ni du per-window — ne pas y mettre le mouvement du focus ou le changement de workspace actif à la souris. Deux lignes de plus depuis le 02/10 : **`slow AX <attribut> → <app>: N ms`** (tout appel AX > 500 ms, au plus une ligne par app toutes les 10 s — une nuit de `.timing` montrait des décrochages de 0,7–3 s sans jamais dire *quelle* app tenait la ligne) et **`previous run ended in a crash: …`** au démarrage (rapport DiagnosticReports plus récent que le stamp `~/.config/mosaic/.last-start`). Depuis le 03/10, la bascule vers un workspace **déjà affiché** sur son écran laisse aussi une ligne (**`retarget monN: wsK already shown, active wsA → wsK`**) et le warp de la souris se dénonce quand il ne porte pas (**`warp wsK → x,y did not land: cursor at …, CGError n`**, ou **`focused centre … is off its monitor → screen centre`** quand le centre calculé n'est pas sur l'écran cible) : un warp muet se lisait « ma souris reste sur l'autre écran », et `checkSpaceChange` rebasculait le workspace actif dans la foulée.
- **`undo`** (`WindowManager+Undo`) : un instantané (`serialize`) de la workspace **avant** chaque édition structurelle lancée par l'utilisateur — move, swap, resize, toggle-*, group, rotate, equalize, reset, drop intra-workspace — jamais sur un insert ou une fermeture (rien à défaire, et ça ferait sauter l'undo à un moment sans rapport). `UndoRing` pur + testé : coalescence 1,5 s (une rafale de resize = un pas), 10 pas, `pop` par workspace (un instantané d'une autre workspace attend qu'on y soit). Rejoué par `rebuild` (appariement par id dans la session) ; les fenêtres arrivées depuis sont réinsérées, les parties disparues s'effondrent. Un drop cross-workspace n'est pas couvert (deux arbres).
- Commits : **PAS de trailer `Co-Authored-By`**. Style de code : coller au fichier (densité de commentaires, nommage, idiomes existants — les commentaires expliquent le *pourquoi* des pièges).
- Pas de dépendance CGS/Spaces réintroduite dans v2 (le pivot l'a justement supprimée).
- **Jamais un symbole privé hard-linké** (`@_silgen_name`) : tout passe par `PrivateAPI` (`dlsym` à l'exécution, repli `dlopen`). Hard-linké, un symbole qu'Apple retire fait refuser le lancement par dyld, sans message ; résolu à l'exécution, il coûte une capacité — les gestes s'éteignent en silence, le pont AX→window-id manquant produit une alerte claire — et `dump-layout` dit lequel manque. **Sonder l'effet, pas le symbole** : sur macOS 27 `CGSSetWindowAlpha` se résolvait, retournait 0 (succès) et ne changeait rien (relecture `kCGWindowAlpha` = 1.0, mesuré) — une sonde par `dlsym` déclarait donc « ok » une capacité morte ; la sonde a dû poser 0,99 sur une fenêtre étrangère et relire. Depuis, le dim des tuiles inactives ne passe plus par CGS du tout : `TileScrims` (voile noir cliquable-à-travers par tuile, AppKit pur, fondu en place) rend `inactiveOpacity`, et il ne reste que deux entrées privées (pont AX, MultitouchSupport). Toute nouvelle entrée privée se juge sur son effet observé, jamais sur sa résolution.
